Get started

Install the plugin, let the install skill draft the configuration with you, then do the few steps only you can do.

Requirements

  • A GitHub repository with Actions.
  • A Claude subscription token (claude setup-token) or an Anthropic API key.
  • Locally: bash 4+, git, jq and gh.

Install

In Claude Code, from your repository:

/plugin marketplace add codifydoo/gatehand
/plugin install gatehand@gatehand
/gatehand:install

The install skill reads your CI, toolchain and contributor docs, drafts the configuration with you, renders the files on a branch, and walks you through the steps below. Nothing is pushed or changed on GitHub without your go-ahead.

Without Claude Code: clone the repository and run bin/render.sh <your-repo>, then follow the setup yourself.

Setup, in short

The exact commands are under Setup in the runbook.

  1. Create the GitHub App

    Webhook off. Repository permissions: Contents, Issues, Pull requests and Actions read and write; Checks, Commit statuses and Metadata read. Nothing else, and no Workflows. Install it on this repository only.

  2. Install the Claude GitHub App

    On the same repository: the review posts its verdict as claude[bot].

  3. Set the secrets and variables

    The App's private key and client ID, the bot's ID, your login as AGENT_OWNER_LOGIN, and the Claude token.

  4. Create the labels and the runner ref

    bash .github/scripts/agent-labels.sh, then push the default branch to agent-runner.

  5. Set the Actions defaults

    Workflow permissions: "Read repository contents", and untick "Allow GitHub Actions to create and approve pull requests". Every workflow declares its own permissions.

  6. Turn it on

    gh variable set AGENTS_ENABLED --body true. Leave AGENT_AUTO_MERGE unset until you have read a few of the merge gate's dry-run summaries.

  7. After the first agent PR

    Pin the "Needs a human (agent inbox)" issue, and add agent pr guard to the default branch's required status checks.

/gatehand:doctor checks that the setup is complete and consistent: files, secrets, variables, the GitHub App, the runner ref, labels, Actions settings, required checks.

Day to day

  • Queue work: label an issue agent:ready, or file it with the "Agent task" template.
  • Start a run now: gh workflow run agent-coder.yml --ref agent-runner
  • Keep an issue away from the agents: agent:hold.
  • Allow protected paths for one issue: a writer adds agent:allow-protected to the issue.
  • Turn on auto-merge: gh variable set AGENT_AUTO_MERGE --body true
  • Kill switch: gh variable set AGENTS_ENABLED --body false stops every agent job at its next start; the inbox still works.

The inbox

Everything that needs a person lands as a comment on the "Needs a human (agent inbox)" issue. Answer with a comment that starts with a command; only the owner's count.

CommandEffect
/approve REQ-…Do what the request proposes
/reject REQ-… [reason]Leave it as it is
/rerun coder #NRe-queue #N and start the coder on it
/pause <role> · /resume <role>Stop or restart a role (also resets its breaker)

The dashboard (/gatehand:dashboard) has buttons for the same answers, across every repository where Gatehand is installed.

Changing the rules, and updating

  • Numbers, models, schedules, runners, tools: edit policy.json, then re-render with /gatehand:update and commit both.
  • Your project's rules and checks: project.md. The coder and the fixer read it on every run.
  • A new version of Gatehand: /gatehand:update. The changelog says whether installed repositories need one.
  • Never edit the rendered package files: an update refuses to overwrite a hand-edited file.
