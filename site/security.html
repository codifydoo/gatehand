Security model

The model never shares a job with a write-capable token, and nothing it wrote is executed by one. This page is a summary; the runbook has the full text.

The controls

Read-only model job

The job that runs the model has contents: read and no id-token. Push, every gh command, curl, wget, ssh, docker, sudo, WebFetch and WebSearch are denied to it.

A separate publish job

The job with the App token runs only the default branch's scripts. The App has no Workflows permission, so GitHub itself refuses any push that touches .github/workflows/.

Protected paths

Paths you list need a writer's agent:allow-protected on the issue, and such a PR is never auto-merged. Under that is a floor no file can lower: .github/, .claude/, nested CLAUDE.md files, .mcp.json.

Sudo once, before agent code

Your system action is the only setup step that may use sudo. Passwordless sudo is gone before anything the agent wrote runs.

The agent-runner ref

Runs are dispatched on a ref whose cache scope the default branch and PRs never read, and the model's job restores no caches.

The review model cannot write

The review job's token is read-only and the model has no tool that writes. A separate job that runs no model posts the review, and refuses one that carries text shaped like a credential.

Untrusted text

Issue text is framed as data and stripped of invisible format characters; only writers' comments reach the model. Text the bot posts has @mentions and <!-- neutralised.

Trust anchored on a person

The coder takes an issue only if the latest agent:ready came from someone with write access and nobody without it edited the issue since. Inbox commands count only from the owner you name.

The review runs the PR's code

The review checks out the PR and runs code from it with the Claude credential in reach. A dispatched review refuses a fork's PR before the checkout, and on an automatic run GitHub gives a fork's PR no secrets and a read-only token. Fork code still runs on the review runner, so a public repository with a self-hosted review runner should require approval for all external contributors.

Risks you accept by running this

These remain after every control above. Read them before you turn the agents on.

  • The model's own job. A prompt-injected run controls its job and can read the Claude credential from its environment. Use a capped API key if that matters to you, and on self-hosted runners an egress allowlist.
  • CI runs agent code. An agent PR's code runs in your CI like any PR's, without a person reading it first. Keep secrets out of PR-triggered CI jobs, and on self-hosted runners keep the agent pool apart from the CI pool.
  • The review's verdict is a model's. A review that is fooled can still say Approve. The merge gate also needs green CI, the PR guard and no protected path; leave AGENT_AUTO_MERGE off if you want a person to merge every agent PR.
  • Shared subscription. With a Claude subscription token, the runs count against the same subscription as your interactive sessions; runsPerDay is the guard.

Runners

GitHub-hosted runners by default: a fresh VM per job is the isolation the design needs. For your own machines, the hardened-runner add-on says what a self-hosted agent pool must give you, with a reference egress allowlist.

Reporting a vulnerability

Report it privately through GitHub: Report a vulnerability. Please do not open a public issue for a security problem. A report that shows one of the risks above is worse than described is in scope too.
