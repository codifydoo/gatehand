Unattended coding agents, behind a gate.

Gatehand is a Claude Code plugin that installs Claude coding agents into your GitHub repository as plain GitHub Actions workflows. Label an issue, and a coder opens a pull request; a fixer answers red CI and review findings; a merge gate merges it only when every rule agrees.

/plugin marketplace add codifydoo/gatehand
/plugin install gatehand@gatehand
/gatehand:install
Get started How it works

The rule it rests on

The model never shares a job with a write-capable token, and nothing it wrote is executed by one. Each coder run is three jobs. Only the middle one runs the model.

  1. Preflight

    no modelApp token

    Checks the kill switch, the daily caps and the breaker, picks one agent:ready issue, locks it and reads it once.

  2. Code

    the modelread-only token

    Edits, tests and commits on a local branch. It cannot push, comment or label, and every gh command is denied to it.

  3. Publish

    no modelApp token

    A fresh checkout of your default branch validates the commits and opens the PR, with a GitHub App that has no Workflows permission.

It came out of running exactly this, unattended, on a production codebase. The security model lists every control, and the risks that remain.

What runs in your repository

Coder

Turns agent:ready issues into pull requests that say Refs #N.

Fixer

Answers red CI and review findings on the agents' own PRs, a capped number of times.

Claude review

Reviews every PR once. Its verdict gates the merge.

Merge gate

Merges an agent PR only when CI, the review and every rule agree. A dry run until you turn it on.

PR guard

A check on every agent PR: protected paths, Refs #N, no closing keywords, and your own rules.

Inbox

One issue where everything that needs a person lands. You answer with /approve, /reject, /rerun, /pause, /resume.

Digest

A weekly comment on the inbox: what waits for you, PRs, runs and cost, the queue.

Sweep

Hourly: frees stale locks, moves issues whose PR merged or closed, recovers dead fix runs.

The logic is in deterministic shell scripts that run without a model; the workflows are thin callers. State lives in GitHub itself: labels, markers in the bot's comments, and JSON rows on an agent-ledger branch.

You stay in charge

  • Off until you turn it on. Nothing runs until AGENTS_ENABLED is true. Set it to false and every agent job stops at its next start.
  • Auto-merge is a second switch. The merge gate only reports what it would do until AGENT_AUTO_MERGE is true.
  • Capped. Runs per day, open PRs, attempts per issue and fixes per PR are limits in your policy.json; a breaker stops a role that keeps failing.
  • Trust starts with a person. The coder takes an issue only if someone with write access applied agent:ready, and nobody without write access edited it since.
  • Protected paths. An agent PR can never touch .github/ or .claude/, and paths you list need a person's label on the issue first.
  • Your files stay yours. Your settings in .github/agents/ are created once and never overwritten; an update refuses to overwrite a package file you edited by hand.

A dashboard on your machine

One local page for every repository where Gatehand is installed: what waits for you, agent PRs and why the merge gate holds each, what is running, the queue, and the week's runs and cost. Its buttons do, with your own gh login, what you would otherwise type on GitHub. It needs gh signed in and Python 3.9 or later: no packages, no build, no server of ours.

/gatehand:dashboard        # in Claude Code
python3 bin/dashboard.py   # from a checkout
