The dashboard

One local page for every repository where Gatehand is installed: what the agents are doing now, what waits for you, and what they did this week, with buttons for the answers you would otherwise type on GitHub.

Start it

/gatehand:dashboard        # in Claude Code
python3 bin/dashboard.py   # from a checkout of the package

It needs gh signed in and Python 3.9 or later, nothing else: no packages, no build, no server of ours. It opens your browser on 127.0.0.1. Nothing of it is installed into your repositories.

On first start it lists every repository your login can see and keeps the ones where Gatehand is installed. "Find repositories" scans again; you can add one by hand as owner/name, or hide one. The page refreshes every five minutes while it is visible, and the server stops after two hours with no page open.

Options

OptionWhat it does
--port NListen on this port (default: a free one)
--no-openDo not open a browser; print the address instead
--print-urlPrint the address with its secret
--idle-minutes MStop after M minutes with no page open (default 120; 0 never)
--config FILEKeep the repository list here
--ready-file FILEWrite {port, token} there once listening, for scripts

What it shows

Totals

Repositories, items waiting for you, open agent PRs, queued issues, runs now, and runs and cost over seven days.

Waiting for you

Open inbox requests, stopped roles, blocked issues and PRs, candidate issues, and merged issues to close once live: the same list the weekly digest posts.

Repositories

For each one: the installed version, whether the agents and auto-merge are on, runs today against each role's daily cap, seven-day cost, breakers and health.

One repository

Its inbox requests in full, agent PRs with the merge gate's last word on each, running and recent runs, the queue by priority, and what is in progress, blocked or on hold.

Numbers are computed the way the agents compute them. A part it cannot read is shown as ? and listed under the repository, never as zero, "off" or "nothing waits".

What you can do from it

Every button asks you to confirm, says what will happen, and then does it with your own gh login. The agents see exactly what they would see if you had done it on GitHub, and apply the same rules.

A button the agents would ignore from you is shown disabled, with the reason. Runs, verdicts, closes and the two switches are previewed first: the server shows each GitHub call it will make, and makes it only if nothing changed in between.

The page never adds agent:ready. That label vouches for the issue's text as it stands, and the page does not show that text, so queueing an issue stays on GitHub, next to it.

How it is kept private

The server can read everything your gh login can, so the page is built so that nothing but the tab it opened can talk to it.

  • It listens on 127.0.0.1 only.
  • Every request needs a per-launch secret. It travels in the address's fragment, which is never sent to any server, and is removed from the address bar once the page has it.
  • A site that rebinds its DNS name to 127.0.0.1 gets nothing, and another site's form or script cannot post to it.
  • Issue titles and request bodies are set only as text, never as HTML, under a strict Content-Security-Policy.
  • Your token never enters the dashboard's process: every call is a gh subprocess.
  • It writes to GitHub only through the buttons above, each a fixed shape the server builds. Reading writes nothing.
